# EblanGPT Bot

Лучший в мире Telegram-бот на AsyncTeleBot (pyTelegramBotAPI).

Доступен как [@EblanGPTrobot](https://t.me/eblangptrobot).

## Запуск

Зависим от Python >= 3.11, для запуска:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

После заполнения `.env`, запустить:

```bash
python src/main.py
```

Обязательные настройки в `.env`:

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота ([@BotFather](https://t.me/BotFather])) |
| `AI_API_KEY` | Ключ текстового API |
| `AI_API_URL` | Полный адрес Chat Completions в OpenAI-совместимых провайдерах, например `https://api.openai.com/v1/chat/completions` |
| `AI_MODEL` | Название модели у выбранного провайдера |

Для изображений нужен `OPENROUTER_API_KEY`, для голосовых — `GROQ_API_KEY`. Без этих ключей бот продолжает отвечать на текст и сообщает, что соответствующее распознавание не настроено. Vision-модель, резервные модели, модель расшифровки и лимиты задаются в `.env.example`.

Админские команды доступны пользователю с `ADMIN_USER_ID`. Если ID не задан, используется `ADMIN_USERNAME`. Если обе настройки пустые, админские команды недоступны.

`.env` загружается из корня проекта, относительные пути тоже разрешаются от корня.

## Возможности

- Личные диалоги с историей и потоковой выдачей.
- Rich Markdown, таблицы, код и формулы; обычный текст как резервный способ отправки.
- Ответы в группах на обращения в начале сообщения, упоминание бота и reply на его сообщение.
- Случайные ответы через настраиваемый интервал сообщений; интервал переживает перезапуск.
- Фоновое сохранение группового контекста с именем и ID отправителя.
- Фото и изображения-документы, вопросы по ним через подписи и reply, резервные vision-модели.
- Голосовые, аудиозаписи и аудиодокументы; в группах — фоновая расшифровка и вызов бота голосом.
- Текстовые файлы в UTF-8/CP1251 и геолокация.
- Guest-вызовы с цитатами, связанными сообщениями и медиа.
- Приветствия с картинками, события вступления и выхода участников.
- Статистика и рассылки, включая копирование сообщений с медиа.
- Фоллбеки для таймаутов, сетевых ошибок, отказа авторизации, ограничений API и ошибок вложений.

> Для фонового чтения сообщений в группах бот должен иметь доступ к этим сообщениям: надо проверить настройки privacy в BotFather или права администратора. Guest-режим также требует соответствующей настройки бота в Telegram.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Приветствие, описание возможностей и кнопки |
| `/clear` | Очистка истории текущего чата или текущей темы форума |
| `/stats` | Статистика, только для админа |
| `/broadcast текст` | Рассылка активным личным чатам, только для админа в личке |
| `/broadcast` как reply | Копирование сообщения в рассылку |

В группах бот реагирует на начальные обращения `вась`, `уась`, `еблан`, `гпт`, `вася` и их продолжения, на начальное `@имя_бота` и на ответы своему сообщению. Обычные сообщения попадают в контекст; случайный ответ по умолчанию происходит через 10–20 подходящих сообщений. Голосовые могут вызывать бота через распознанную речь.

## Хранение

SQLite автоматически создаётся в `data/eblangpt.sqlite3`. В ней хранятся история, чаты для рассылки, счётчики и состояние случайных ответов. Старые диалоги доступны после перезапуска процесса. История разделяется по чату и теме форума.

По умолчанию остаётся до 30 сообщений и 8000 символов истории. Системный промпт не хранится в истории и добавляется к каждому запросу отдельно. Неудачные генерации и фоллбеки не записываются как ответы модели. `/clear` ждёт текущую обработку этого диалога и затем удаляет историю из базы.

Guest-запросы используют только приложенный контекст и не записываются в обычную историю. В группе контекст общий для её участников; в форуме — отдельный для каждой темы.

## Структура

```text
src/
  main.py                  запуск, HTTP-сессия, регистрация хендлеров
  config.py                настройки окружения
  prompt.py                системный промпт
  database.py              SQLite
  handlers/
    commands.py            /start и /clear
    messages.py            личные текстовые сообщения
    groups.py              текстовые сообщения в группах
    media.py               обработка вложений
    guest.py               guest-вызовы
    admin.py               статистика и рассылки
    events.py              события групп
  services/
    ai.py                  Chat Completions и потоковый ответ
    media.py               скачивание и распознавание вложений
    history.py             история и блокировки диалогов
    context.py             извлечение текста и формирование контекста
    chats.py               учёт чатов и вызовы в группах
    replies.py             генерация и сохранение ответа
    telegram.py            форматирование и доставка сообщений
    errors.py              фоллбеки
    emojis.py              постобработка коротких ответов
assets/                    картинки приветствий
tests/                     проверки без Telegram и внешних моделей
```

## Проверки

```bash
python -m unittest discover -v
```

Тесты используют временную базу, подставной Telegram-клиент и локальный HTTP-сервер. Они проверяют перезапуск истории, разделение чатов и тем, очистку во время генерации, SSE, вложения, групповые вызовы, guest-контекст, ограничения админа, рассылки и закрытие сессий.

Внешние возможности зависят от доступности выбранных моделей и прав бота в Telegram. Длинные обычные ответы разбиваются на сообщения; guest-ответ ограничивается одним сообщением. Форматирование при разделении длинного ответа может перейти в обычный текст.
